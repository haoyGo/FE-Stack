## 🎯 技术选型方法论

### Q1: 如何进行技术选型？你的决策依据是什么？

**答题思路**：展现系统性思维和实战经验

#### 1️⃣ 评估维度框架（SMART 原则）

```
技术选型决策模型：
┌─────────────────────────────────────────┐
│ 1. 业务场景 (Business Context)          │
│    - 项目类型：ToB/ToC/内部系统         │
│    - 性能要求：首屏时间/交互响应        │
│    - 用户规模：百/万/千万级             │
│    - 业务复杂度：CRUD/中台/大型应用     │
├─────────────────────────────────────────┤
│ 2. 团队能力 (Team Capability)           │
│    - 技术储备：现有技能栈               │
│    - 学习成本：培训周期                 │
│    - 开发效率：开发/调试/维护成本       │
├─────────────────────────────────────────┤
│ 3. 技术成熟度 (Technology Maturity)     │
│    - 社区活跃度：GitHub Stars/Issues   │
│    - 生态完善度：周边工具/组件库        │
│    - 企业采用率：大厂案例               │
│    - 长期支持：版本迭代/向后兼容        │
├─────────────────────────────────────────┤
│ 4. 架构适配性 (Architecture Fit)        │
│    - 可扩展性：模块化/插件化            │
│    - 可维护性：代码组织/测试覆盖        │
│    - 技术债务：迁移成本                 │
├─────────────────────────────────────────┤
│ 5. 成本收益 (Cost-Benefit)              │
│    - 开发成本：人力/时间                │
│    - 运维成本：部署/监控                │
│    - 机会成本：试错成本                 │
└─────────────────────────────────────────┘
```

#### 3️⃣ 关键决策点

**示例：中后台管理系统选型**

| 维度         | React                   | Vue 3                   |
| ------------ | ----------------------- | ----------------------- |
| **性能**     | ⭐⭐⭐⭐ (Fiber)        | ⭐⭐⭐⭐⭐ (响应式)     |
| **生态**     | ⭐⭐⭐⭐⭐ (最丰富)     | ⭐⭐⭐⭐ (成熟)         |
| **学习曲线** | ⭐⭐⭐ (JSX/Hooks)      | ⭐⭐⭐⭐⭐ (易上手)     |
| **类型支持** | ⭐⭐⭐⭐ (TS 支持好)    | ⭐⭐⭐⭐ (原生支持)     |
| **企业级**   | ⭐⭐⭐⭐ (灵活但需规范) | ⭐⭐⭐⭐ (Element Plus) |
| **最佳场景** | 复杂交互/数据流密集     | 快速迭代/渐进式开发     |

**决策结论**：

- **选 React**：团队有 React 经验 + 需要灵活定制 + 复杂状态管理 + 丰富的生态
- **选 Vue 3**：团队新手多 + 快速交付 + 渐进式引入 + 注重开发体验

### Q3: React vs Vue 底层原理差异对架构的影响？

```
前端架构选型决策树：
┌─────────────────────────────────────────────────────────┐
/**
 * 响应式系统差异
 */

// Vue 3 - Proxy 响应式（细粒度）
class VueReactivity {
  private data = reactive({
    count: 0,
    list: [],
  });

  // ✅ 优势：自动追踪依赖，精准更新
  // 组件粒度：只更新变化的属性对应的 DOM
  updateCount() {
    this.data.count++; // 只触发 count 相关的更新
  }
}

// React - 状态不可变 + 虚拟 DOM（组件级）
class ReactComponent {
  state = {
    count: 0,
    list: [],
  };

  // ⚠️ 整个组件重新渲染（需要手动优化）
  updateCount = () => {
    this.setState({ count: this.state.count + 1 });
    // 触发整个组件的 render 函数
  };

  // 优化手段：
  shouldComponentUpdate(nextProps, nextState) {
    return this.state.count !== nextState.count;
  }
}
```

```typescript
/**
 * 插件化架构核心
 */
interface Plugin {
  name: string;
  version: string;
  install: (app: App, options?: any) => void;
  uninstall?: () => void;
}

class PluginSystem {
  private plugins: Map<string, Plugin> = new Map();
  private hooks: Map<string, Function[]> = new Map();

  // 注册插件
  use(plugin: Plugin, options?: any) {
    if (this.plugins.has(plugin.name)) {
      console.warn(`Plugin ${plugin.name} already registered`);
      return;
    }

    plugin.install(this.app, options);
    this.plugins.set(plugin.name, plugin);

    // 触发生命周期
    this.trigger("plugin:installed", plugin);
  }

  // 事件系统
  on(event: string, handler: Function) {
    if (!this.hooks.has(event)) {
      this.hooks.set(event, []);
    }
    this.hooks.get(event)!.push(handler);
  }

  trigger(event: string, ...args: any[]) {
    const handlers = this.hooks.get(event) || [];
    handlers.forEach((handler) => handler(...args));
  }
}

/**
 * 实战案例：监控插件
 */
const monitorPlugin: Plugin = {
  name: "monitor",
  version: "1.0.0",

  install(app, options) {
    // 注入全局 API
    app.config.globalProperties.$monitor = {
      trackEvent(name: string, data: any) {
        console.log("[Monitor]", name, data);
        // 发送到监控平台
      },
    };

    // 路由监控
    app.router.beforeEach((to, from) => {
      performance.mark("route-start");
    });

    app.router.afterEach((to, from) => {
      performance.mark("route-end");
      performance.measure("route-duration", "route-start", "route-end");

      const duration =
        performance.getEntriesByName("route-duration")[0].duration;
      this.$monitor.trackEvent("route-change", {
        from: from.path,
        to: to.path,
        duration,
      });
    });

    // 错误监控
    app.config.errorHandler = (err, vm, info) => {
      this.$monitor.trackEvent("error", {
        message: err.message,
        stack: err.stack,
        info,
      });
    };
  },
};
```

```typescript
/**
 * 完整的微前端架构方案
 */
class MicroFrontendArchitecture {
  // 1. 应用注册中心
  private registry: Map<string, MicroApp> = new Map();

  // 2. 通信总线
  private eventBus = new EventEmitter();

  // 3. 共享状态
  private sharedState = reactive({
    user: null,
    permissions: [],
    theme: "light",
  });

  /**
   * 注册子应用
   */
  register(app: MicroApp) {
    // 规范化配置
    const normalizedApp = this.normalizeConfig(app);

    // 预加载资源
    if (normalizedApp.preload) {
      this.prefetchResources(normalizedApp);
    }

    // 生命周期管理
    this.setupLifecycle(normalizedApp);

    this.registry.set(app.name, normalizedApp);
  }

  /**
   * 沙箱隔离
   */
  createSandbox(appName: string) {
    // Proxy 沙箱
    const fakeWindow = new Proxy(window, {
      get(target, prop) {
        // 优先从沙箱读取
        if (sandbox.has(prop)) {
          return sandbox.get(prop);
        }
        return Reflect.get(target, prop);
      },
      set(target, prop, value) {
        // 写入沙箱
        sandbox.set(prop, value);
        return true;
      },
    });

    return {
      window: fakeWindow,
      document: fakeDocument, // 代理 document
      location: fakeLocation, // 代理 location
    };
  }

  /**
   * 样式隔离
   */
  isolateStyles(app: MicroApp) {
    // 方案 1: Shadow DOM
    const shadowRoot = app.container.attachShadow({ mode: "open" });
    shadowRoot.innerHTML = app.html;

    // 方案 2: CSS Modules with Prefix
    const styles = app.styles.map((css) =>
      this.prefixCSS(css, `[data-app="${app.name}"]`)
    );

    // 方案 3: Dynamic Scoped CSS
    const styleElement = document.createElement("style");
    styleElement.setAttribute("data-app", app.name);
    styleElement.textContent = styles.join("\n");
    document.head.appendChild(styleElement);
  }

  /**
   * 应用通信
   */
  setupCommunication() {
    // 方案 1: 事件总线
    this.eventBus.on("user:login", (user) => {
      this.sharedState.user = user;
      // 通知所有子应用
      this.broadcast("state:changed", { user });
    });

    // 方案 2: 共享状态（Props）
    const provide = {
      globalState: this.sharedState,
      eventBus: this.eventBus,
      router: this.router,
    };

    // 方案 3: LocalStorage + Storage Event
    window.addEventListener("storage", (e) => {
      if (e.key === "shared-state") {
        this.syncState(JSON.parse(e.newValue));
      }
    });
  }

  /**
   * 性能优化
   */
  optimize() {
    // 1. 预加载
    this.prefetchApps(["app1", "app2"]);

    // 2. 按需加载
    this.lazyLoadApp("app3");

    // 3. 缓存策略
    this.cacheStaticAssets();

    // 4. 共享依赖
    this.setupSharedDependencies(["react", "react-dom"]);
  }
}
```

### Q6: Redux vs Zustand vs Pinia 如何选择？

#### 状态管理方案对比

```typescript
/**
 * Redux - 严格单向数据流
 */
// ✅ 优势：可预测、可追溯、生态丰富
// ❌ 劣势：样板代码多、学习曲线陡

// 1. Action Types
const INCREMENT = "counter/increment";

// 2. Actions
const increment = (amount: number) => ({
  type: INCREMENT,
  payload: amount,
});

// 3. Reducer
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case INCREMENT:
      return { value: state.value + action.payload };
    default:
      return state;
  }
}

// 4. Store
const store = createStore(counterReducer);

// 5. 使用（React）
function Counter() {
  const value = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return <button onClick={() => dispatch(increment(1))}>{value}</button>;
}

/**
 * Zustand - 简化版状态管理
 */
// ✅ 优势：零样板代码、体积小、API 简单
// ⚠️ 注意：缺少中间件生态

import create from "zustand";

const useStore = create((set) => ({
  count: 0,
  increment: (amount) =>
    set((state) => ({
      count: state.count + amount,
    })),

  // 支持异步
  fetchUser: async (id) => {
    const user = await api.getUser(id);
    set({ user });
  },
}));

function Counter() {
  const { count, increment } = useStore();
  return <button onClick={() => increment(1)}>{count}</button>;
}

/**
 * Pinia - Vue 3 官方状态管理
 */
// ✅ 优势：TypeScript 友好、Dev Tools 支持、模块化
// 🎯 Vue 生态首选

import { defineStore } from "pinia";

export const useCounterStore = defineStore("counter", {
  state: () => ({
    count: 0,
    user: null,
```

### Q7: Webpack vs Vite vs Turbopack 的本质区别？

#### 构建工具原理对比

```typescript
/**
 * Webpack - Bundle Based（打包式）
 */
// 原理：分析依赖 → 构建依赖图 → 打包输出
// ❌ 冷启动慢（需要构建整个依赖图）
// ✅ 生态成熟、插件丰富

  entry: "./src/main.js",
  output: {
    filename: "bundle.js",
    path: "/dist",
  },
  module: {
    rules: [
      // 每个文件都要经过 loader 处理
      { test: /\.tsx?$/, use: "ts-loader" },
      { test: /\.css$/, use: ["style-loader", "css-loader"] },
    ],
  },
  plugins: [
    // 丰富的插件生态
    new HtmlWebpackPlugin(),
    new MiniCssExtractPlugin(),
  ],
};

/**
 * Vite - Native ESM（原生模块）
 */
// 原理：利用浏览器原生 ESM + esbuild 预构建
// ✅ 冷启动快（按需编译）
// ✅ HMR 速度快（精准更新）
// ⚠️ 生产环境用 Rollup 打包

// Dev Server 原理
class ViteDevServer {
  async transformModule(url: string) {
    // 1. 按需编译（只编译当前请求的模块）
    const code = await readFile(url);

    // 2. esbuild 转换（快！）
    const transformed = await esbuild.transform(code, {
      loader: "tsx",
      target: "es2020",
    });

    // 3. 浏览器直接执行 ESM
    return {
      code: transformed.code,
      map: transformed.map,
    };
  }

  // HMR 原理
  async handleHMR(changedFile: string) {
    // 只重新编译变化的模块
    const affectedModules = this.moduleGraph.getAffectedModules(changedFile);

    for (const mod of affectedModules) {
      await this.transformModule(mod.url);
      // 推送更新到浏览器
      this.ws.send({
        type: "update",
        updates: [{ type: "js-update", path: mod.url }],
      });
    }
  }
}

/**
 * Turbopack - Incremental (增量式，Rust)
 */
// 原理：函数级缓存 + 增量计算 + Rust 并行
// ✅ 号称比 Vite 快 10 倍（待验证）
// ⚠️ 还在 alpha 阶段

// 增量计算原理
function turbopackPrinciple() {
  // 1. 函数级缓存
  const cache = new Map();

  function transform(file) {
    if (cache.has(file.hash)) {
      return cache.get(file.hash); // 命中缓存
    }

    const result = doTransform(file);
    cache.set(file.hash, result);
    return result;
  }

  // 2. 并行处理（Rust 多线程）
  // 3. 智能失效（只重算变化的函数）
}
```

```javascript
 * 选型决策树
 */
function selectBuildTool(project) {
  // 1. 新项目 → Vite（无历史包袱）
  if (project.isNew) {
    return "Vite";
  }

  // 2. 老项目 + 复杂配置 → Webpack（稳定）
  if (project.hasComplexConfig || project.hasLegacyPlugins) {
    return "Webpack 5";
  }

  // 3. Next.js 项目 → Turbopack（官方支持）
  if (project.framework === "Next.js") {
    return "Turbopack (experimental)";
  }

  // 4. 需要极致优化 → 混合方案
  return {
    dev: "Vite", // 开发快
    build: "Webpack", // 生产稳
  };
}
```

## 📚 总结

**架构选型核心原则**：

1. **业务优先**：技术服务于业务，不过度设计
2. **团队匹配**：选择团队熟悉的技术栈

4. **可维护性**：代码可读、可测、可扩展
5. **性能平衡**：开发效率 vs 运行效率
